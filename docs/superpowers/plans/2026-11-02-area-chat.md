# Чат района и записки — план v1

Спецификация: `docs/superpowers/specs/2026-11-02-area-chat-design.md` (согласована,
решения владельца там же). Этот план — как её v1 ложится на код. Всё, что
спецификация помечает «не в v1» / «позже» (публичная комната по Bluetooth,
личные сообщения, компьютер, совместимость с bitchat, перенос вида рации),
здесь не делается.

## Провод

Сверено по `wire-protocol`: ни `FrameType`, ни cipher-тега, ни
`InnerPayloadType`, ни URI `cubechat:` — чат района не проходит через mesh и
`MessagingService`. Новое — только виды Nostr на отдельном релее `/area`:

| Вид | Что |
|---|---|
| 1060 | сообщение чата, `expiration` +24 ч, PoW 12 |
| 1062 | записка, `expiration` 1 ч / 24 ч / 7 дн, PoW 16 |
| 21060 | присутствие, эфемерное, PoW 8 |
| 5 | удаление своей записки (NIP-09) |

Старая сборка этих видов не видит вовсе: она не подписана на `/area`, а пул
`NostrRelayClient` пропускает только 1059 (`verifyInboundEvent` не меняется).
В `wire-protocol` — строка «виды Nostr» с занятыми номерами.

Два уточнения к схеме `content` (оба — в сторону меньшего):

- `name` **необязателен**: без него читатель выводит имя из ключа сам
  («Кубик-4F2A» на своём языке). Иначе имя по умолчанию выдавало бы язык
  пишущего. Своё имя, если человек его задал, идёт в `name`.
- Жалоба из чата района подписывается **одноразовым** ключом (не ключом
  района): серверу жалоб не нужно связывать жалобу даже с временным именем
  жалующегося. PoW 16, лимит по IP — как в спецификации.

## Части

1. **Релей** (`relay/`): `area-policy.mjs` + тесты — виды, PoW, `g`, `cell`,
   `expiration`, размер, лимиты по IP, ключи из `banned-area.json`;
   `deploy/strfry-area.conf` (порт 8083, retention 1060 — 24 ч, 1062 — 7 дн),
   `cubechat-area-relay.service`, блок `/area` в Caddy (без журнала); README.
2. **push/**: `ReportContext.area` (`target` = ключ района, `eventId`,
   `geohash`, PoW 16, 10 в час с IP), отдельный `createAreaBans` и подписанный
   `GET /banned/area` (id и ключи за 24 ч), решение «Забанити» для `area` идёт
   туда, а не в общий `/banned`, и пишет файл для `area-policy`; бот знает
   контекст `area`. Тесты.
3. **Домен** (`lib/features/area/domain/`): геохеш (кодирование, границы,
   соседи, антимеридиан), уровни, кодек событий и `verifyAreaEvent`
   (5 ступеней, Schnorr последним), потолки исходящих, комнаты в памяти с
   пределами 300/500/100 и флудом, локальные лимиты отправки.
4. **Данные** (`lib/features/area/data/`): ключи района (CSPRNG, на
   (клетку, уровень), ≤ 6 ч, бокс настроек, стирание), настройки (выключатель,
   согласие, «Показувати, що я тут» — выкл.), место (приблизительный фикс →
   геохеш 5 в одной функции, гистерезис 2 фикса, только пока экран открыт,
   раз в 5 мин), бан-лист `/banned/area`, жалоба, свои записки, контроллер.
   Сокет — `lib/core/transport/nostr/area_relay_link.dart` (свой, как у рации;
   кадр ≤ 64 KiB; 30 с задержки закрытия).
5. **Интерфейс**: кнопка «Поруч» на карте, лист уровней, экран чата, чтение
   чужого города долгим нажатием, согласие, записки (список, создание, выбор
   района на карте), контуры клеток с числом записок, выключатель в
   «Конфіденційність і безпека», экстренная очистка. Строки — en и uk.
6. **Документы**: политика (en/uk), условия (en/uk), `store-disclosures.md`,
   `README.md` (модель угроз), `relay/README.md`.

## Тесты

`area_geohash_test`, `area_event_test` (потолки, схема, `verifyAreaEvent` по
ступеням, Schnorr не зовётся без PoW), `area_keys_test` (не ключ аккаунта /
Nostr / устройства, разные на уровни и клетки, срок, смена по кнопке,
стирание), `area_room_test` (пределы на 10 000 ключей, флуд, счёт),
`area_controller_test` (присутствие выключено по умолчанию, чужой город —
только подписка, ничего в ответ на входящее, записка без ручного района —
без `cell`), `area_location_test` (огрубление, гистерезис), relay и push —
`node --test`.

## Чего нет в этом заходе

- **Этап 0 — замер на телефоне** (PoW 8/12/16, Schnorr, сокет): сборки нет по
  просьбе владельца. Числа у констант — исходные из спецификации и замер на
  Mac; помечены «замерить на телефоне до выпуска».
- **Развёртывание** релея и push — файлы в репозитории, на дроплет не
  выкладывается.
- «Только вживую» из спецификации (два телефона в одном городе) — после сборки.
